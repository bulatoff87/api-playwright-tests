# API Playwright tests

Два API-теста Swagger Petstore на TypeScript. Используется только встроенная
фикстура `request` (APIRequestContext); установка браузеров не нужна.

## Запуск

```sh
npm ci
npx playwright test
npm run typecheck
```

`playwright.config.ts` задаёт baseURL, таймауты, один worker и отсутствие retries.
Относительные пути `pet/...` сохраняют `/api/v3/` в baseURL.

## Проверки

1. Позитивный тест создаёт питомца со случайным числовым ID через POST,
   проверяет статус 200, выполняет GET и проверяет статус 200, id и name.
   В finally удаляет своего питомца и проверяет статус удаления 200.
2. Негативный тест использует новый случайный отрицательный ID (допустимый int64,
   контракт не задаёт minimum), который тесты не создавали. Ожидает HTTP 404.

На общедоступном сервере абсолютная гарантия отсутствия чужого ID невозможна;
случайный ID из большого диапазона делает коллизию крайне маловероятной.
Ответ 200 в негативном тесте не считается успехом.

Учебный пример содержит только основные проверки без дополнительной диагностики.
HTML-отчёт: `npx playwright show-report`.

Контракт: https://petstore3.swagger.io/api/v3/openapi.json
APIRequestContext: https://playwright.dev/docs/api-testing

## Наблюдаемая особенность сервера

При запуске 16.09.2026 GET отсутствующего питомца вернул HTTP 404 и обычный
текст `Pet not found`, хотя Content-Type содержал `application/json`.
Первоначальный разбор по Content-Type завершился ошибкой JSON.parse.
В упрощённом негативном тесте проверяется только статус 404, тело не разбирается.
Контракт OpenAPI для 404 не задаёт ни схему, ни media type.
